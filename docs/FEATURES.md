# 功能与使用方式

这份文档说明 superagent 每个模块**能做什么、怎么用、边界在哪**。部署步骤见 [`../deploy/README.md`](../deploy/README.md)，组件与安全设计见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 1. 接活：一个请求怎么进来

| 来源 | 接入方式 | 说明 |
| --- | --- | --- |
| 飞书 | WebSocket 长连接或 HTTP 回调 | 群聊默认只处理 @ 机器人；可切换为接收全部消息；支持话题和续聊 |
| Gmail | IMAP 轮询 + SMTP 回信 | 只接受白名单发件人；附件大小可配；回复进入原工单 |
| CLI | `sa ask` 等命令 | 走本机控制端口，适合脚本和终端 |
| 控制台 | 「发任务」表单 | 可选项目、模型、密钥、目标和协作开关 |

受理不是「收到就干」：

1. Source 先丢掉 bot 自己发的消息，按 trigger 去重。
2. 确定性 gate 按来源、发送者、群、关键词和规则过滤。
3. 需要时让研判模型判断「是不是针对这个项目、是不是明确要求实现、方向是否已定」；拿不准就只记录。
4. 接受后生成不可变 Mandate，记下规则版本、来源、发起人、范围和强度。
5. 之后所有执行、预算和密钥授权都以这张 Mandate 为准。

规则在「设置 → 规则」里改；每次受理或忽略的理由都能在「判断记录」里回看。

## 2. 工单：任务的基本单位

一张工单包含：

- **来源**：哪个渠道、哪条消息、哪个线程。
- **授权**：Mandate（强度、规则版本、发起人、范围）。
- **执行**：一个或多个 Assignment；每个 Assignment 对应一次执行器启动。
- **输入**：人的回复、补充说明、停止原因。
- **输出**：报告、交付物、预览链接、PR 链接。
- **成本**：每次模型调用的 token、缓存命中、延迟和美元金额。

常用操作：

| 操作 | 控制台 | CLI |
| --- | --- | --- |
| 发任务 | 发任务 | `sa ask "<text>" [--wait] [--model provider/model]` |
| 查看 | 任务列表 / 任务页 | `sa tickets`、`sa ticket <id>` |
| 回答 | 任务页输入框 | `sa answer <id> "<text>"` |
| 停止 | 更多 → 停止任务 | `sa stop <id> [reason]` |
| 重试 | 更多 → 重试 | `sa retry <id>` |
| 删除 | 更多 → 删除任务 | `sa delete <id> [--keep-workspace]` |

任务停止后不会被普通消息悄悄恢复；人重新打开或明确回复才会继续。

## 3. 隔离执行：每张票一个沙箱

- 执行器默认是 Pi（`pi --mode rpc`），每张票一个 rootless Podman 容器。
- 容器名是 `sa-<ticketId>`，工作区挂到 `/workspace`；state 目录不挂载。
- 根文件系统只读，只有 `/tmp`、`/home/pi` 和两个挂载点可写。
- `--no-new-privileges`、PID 限制、CPU/内存上限。
- 网络用 pasta，只把网关和 MCP 两个端口从容器回环转到主机回环；后台端口、控制端口和主机其它服务不可达。
- 每次启动生成随机票令牌；令牌随 Assignment 结束失效。
- 容器里只有这张票授权的密钥名和值；值不会出现在页面、事件、日志或错误里。

`maxSlots` 控制并发；任务结束后可以保留或删除工作区。

## 4. 多模型协作：主 AI 自己决定叫谁

开启协作后，运行时会把 `deploy/pi-ext/collab.ts` 拷进这张票的 Pi 配置目录，并写入角色表 `collab.json`。主 AI 通过 `subagent` 工具派活，支持：

- **单个**：`{ agent, task }`
- **并行**：`{ tasks: [...] }`，最多 `maxConcurrent` 个（默认 2）
- **串联**：`{ chain: [...] }`，用 `{ previous }` 把上一步结果交给下一步

默认角色：

| 角色 | 权限 | 适合的活 |
| --- | --- | --- |
| 侦察 `scout` | 只读 | 大范围找文件、函数、配置、资料，返回路径和行号 |
| 规划 `planner` | 只读 | 读代码后给方案、步骤、验证方法和风险 |
| 审查 `reviewer` | 只读 + 命令 | 看 diff、读代码、跑只读测试，按严重程度列问题 |
| 顾问 `advisor` | 只提问 | 不看文件，只回答难题和方案取舍 |
| 帮手 `helper` | 可写 | 批量改名、补测试、改格式；一次只跑一个 |

每个角色可以单独指定模型；未指定或模型被禁用时跟随任务模型。子代理：

- 有独立上下文，只把最终结论交回主 AI；
- 启动时带 `--no-mcp --no-extensions --no-approve`，看不到 `sa_*` 工具，也不能继续派活；
- 令牌带 `.<角色>` 后缀，网关按角色记账，工人 MCP 端点直接拒绝；
- 只有可写角色能拿到这张票授权的密钥；
- 调用次数受 `maxCalls`（默认 20）限制。

控制台的任务过程页会显示「子代理在干活」、角色、模型和状态；任务详情按角色列出花费。

## 5. 目标验收：没达成就不结束

发任务时可以设目标：

- **目标文本**：要达成什么，写成人能验收的话。
- **验收命令**：一行一条，在执行者容器内的 `/workspace` 里按顺序跑，全部退出码为 0 才算过；每条默认最多 10 分钟。
- **判定方式**：`commands+ai`（默认，有命令时）、`commands`、`ai`。
- **上限**：轮数（默认 8）、花费（默认 $3）、时长（默认 6 小时）。

流程：

```text
执行者报 ready
  → 宿主在容器里跑验收命令
  → 命令全过？→ 判定模型逐条核对证据
  → 通过：按 ready 结束任务
  → 没通过：记一轮，把「差什么 + 命令输出」发回执行者
  → 到上限：报 blocked，问你「再给一批轮数、改目标，还是结束」
```

补充规则：

- 执行者报 `failed` / `dropped` 也会先过关卡；没达成就让它换办法继续。
- `blocked` 带问题时不消耗轮数，照常问你。
- 一轮结束没交付，宿主会推它继续；检查期间看门狗不会误杀。
- 同一轮已经在检查时又来的报告，只回复「正在检查」，不会开第二次检查。
- 判定调用记在这张票上，账本 `agent` 为 `goal`。

任务页有目标卡：状态、轮数、花费、截止时间、每条命令的 ✓/✗、还差什么、历史和修改/取消入口。

## 6. 写小说：确定性流水线 + 模型生成

小说功能默认关闭，在「设置 → 小说」打开。它支持仙侠/玄幻，目标是几百到上千章的长篇。

### 6.1 开书与推进

- **一句灵感开书**：书库 → 开新书，填灵感、题材、每章字数、卷数和每卷章数、写手模型。
- **先生成设定书**：世界观、人物、境界、物品、伏笔、卷/弧规划；确认后才开第一张工单。
- **也可以导入设定文档**：`POST /api/novels/import` 或在书库页导入。
- **一弧一票**：每写一弧开一张工单，照常走 Eval、Mandate、预算和渠道通知；小说票和普通任务在同一个列表里。
- **下一弧**：书页显示下一弧的标题、章数和状态，可以写一句要求后开票。

### 6.2 每章流水线

```text
contract → draft → lint → review → [revise → lint → review] ×≤2 → extract → validate → commit
```

| 步骤 | 谁做 | 做什么 |
| --- | --- | --- |
| contract | 规划模型 | 根据弧计划、上章交接、到期伏笔和节奏历史生成本章合同；代码校验后封存 |
| draft | 写手模型 | 输出正文；截断时从断点续写；上游错误按 408/429/5xx 退避 |
| lint | 代码 | 检查 AI 味、重复、禁用表达、字数等 |
| review | 审稿模型 | 按维度输出带原文引用的 JSON 问题清单；引用对不上原文的条目会被丢弃 |
| revise | 写手模型 | 有阻塞问题或问题达到阈值时改写全章；最多 `maxRevisions` 轮；改得太短会丢弃 |
| extract | 抽取模型 | 输出本章增量（人物、物品、境界、时间、伏笔、秘密） |
| validate | 代码 | 对照 canon 做硬校验；事实错误绝不提交 |
| commit | 代码 | 先存快照，再写正文、canon、摘要、全文索引和章节行；幂等 |

硬校验包括：死人出场、境界倒退或跳级、使用不存在的物品、时间倒流、伏笔状态错乱、人物已知秘密越界等。硬伤会交给修订重写；仍不过就暂停全书并问一个问题。审稿意见是主观判断，修订轮数用完仍有阻塞项时，会带 `flagged` 标记提交并在弧报告里列出，不卡死整本书。

### 6.3 上下文与成本

写手上下文按「稳定 → 易变」排列，尽量命中缓存：

1. 系统提示和文风规则；
2. 书级稳定块（卖点、金手指、主角、境界）；
3. 卷摘要、当前弧计划、本弧已写部分摘要；
4. 出场人物卡、物品、伏笔、读者已知；
5. 最近三章摘要 + 上一章末尾原文；
6. 全文检索召回的相关段落；
7. 本章合同。

规划、写手、审稿、抽取可以分别配模型；审稿尽量用不同家族的模型。每章有输入/输出 token 预算，弧、书和每日有美元上限。

### 6.4 阅读、修改与导出

- 书页显示进度、字数、累计成本、状态和当前工单。
- 章节阅读页可以提修改意见、撤销上一版；「待你看」的章节会标出原因（低分、元文字、字数偏离、硬伤等）。
- 支持按书导出 TXT；章节列表可以筛「只看待你看」。

### 6.5 番茄发布

- 在「密钥」里保存 `FANQIE_COOKIE`（浏览器抓到的整串 Cookie）；控制台只显示是否有效。
- 绑定番茄作品 ID 后，可以勾选章节：
  - **存草稿**（推荐）：到番茄后台确认后再发；
  - **直接发布**：发布后不能在控制台撤回；
  - **定时发布**：至少晚于当前时间 30 分钟。
- 可勾选「声明本章使用了 AI 辅助创作」。
- 每章状态：未同步、已存草稿、已发布、定时中、正文有更新、失败。
- 登录每 30 分钟保活；失效会停止同步并提示更新 Cookie。
- 只使用账号主人提供的 Cookie，不模拟登录，也不绕过验证码。

## 7. 控制台

新控制台默认在根路径，旧版在 `/legacy/`（`SA_WEB=legacy` 可以切回旧版）。

| 页面 | 内容 |
| --- | --- |
| 今日 | 等你回答、工位实况、最近结束、今日花费、上游状态、番茄登录提醒 |
| 任务 | 按状态筛选、搜索、批量删除；进行中任务显示当前步骤和模型 |
| 发任务 | 通用任务 / 写小说；项目、模型、密钥、目标、协作开关 |
| 项目 | ZIP 上传、解压进度、档案、交付物、预览 |
| 会商 | 五角色讨论、任务书编辑、按任务书开工 |
| 书库 | 开书、进度、章节阅读/修改、下一弧、导出 |
| 番茄发布 | 绑定作品、勾选章节、草稿/发布/定时、同步状态 |
| 花费 | 今天/7 天/30 天，按票、按模型、按角色 |
| 密钥 | 新增/修改/删除密钥，查看哪些任务被授权 |
| 连接 | 飞书、邮箱、GitHub、预览的状态和测试 |

| 系统 | 健康、槽位、磁盘、暂停接单、清理工作区、备份 |
| 事件 / 判断记录 | 机器做过的事、每次受理或忽略的理由 |

今日看板用 SSE（`/api/live/stream`）推送；断线时退回 5 秒轮询。控制台是响应式的，手机可用。

## 8. 模型网关与花费

- 服务商支持 OpenAI 兼容接口和 Anthropic Messages 接口；模型可以自动发现，也可以手填。
- worker 的 `models.json` 只有 `sa-<provider>` 条目，指向网关，`apiKey` 是这张票的令牌。
- 网关解析令牌 → 找到票和角色 → 转发到真实上游 → 按请求里的模型查价 → 记账。
- 超单票或每日预算返回 402；worker 拿不到上游密钥。
- 账本记录：调用者、票、角色、模型、输入/输出 token、缓存命中、延迟、美元。
- 任务详情可以按「主 AI / 侦察 / 审查 / 目标」分项查看。

## 9. 项目、会商、密钥、预览与 GitHub

- **项目**：上传 ZIP（默认上限 4 GB，解压 12 GB / 30 万文件），安全解压后生成目录、依赖、入口和风险档案；任务可以绑定项目，worker 只看到项目副本。
- **会商**：需求分析师、架构师、实现工程师、测试与验收、风险与安全五个席位，加一个主持人；默认两轮，可各配模型。会商产出任务书，可以直接开票。
- **密钥库**：AES-256-GCM 加密；每个任务单独授权；出站文本统一脱敏；控制台不显示明文。
- **预览**：任务可以开临时端口（默认 19000–19199，每票最多 2 个），控制台生成链接。
- **GitHub**：按票授权仓库；worker 可以克隆、提交、开 PR；PAT 只在请求头里出现，错误信息会擦除。
- **邮件发送**：任务可以按授权发邮件；发件内容和附件走 outbox。

## 10. 运维与恢复

- **健康检查**：`/api/health`；控制台「系统」页有槽位、磁盘、暂停接单和清理。
- **备份**：启动时和每小时检查；SQLite 用 `VACUUM INTO` 做一致快照，连同 `options.json`、`settings.json`、`admin.json`、vault 和小说正文/设定一起打包；不含 `cli-token`、`pi-config/`、小说快照和工作文件。
- **恢复**：停服务，解包覆盖 `state/`，启动；`cli-token` 会重新生成，后台口令以备份里的 `admin.json` 为准。
- **升级**：同步 `src/ tests/ deploy/ package.json pnpm-lock.yaml`，在主机上跑 `bash deploy/deploy.sh`（安装依赖、类型检查、重启、健康检查）。
- **Pi 升级**：控制台「Pi 版本」页检查 npm、构建新镜像、切换给新任务；正在跑的任务不受影响，切回旧镜像就是回滚。

## 11. 三个典型工作流

### 11.1 带协作的开发任务

```text
发任务（选项目 + 模型 + 开协作）
  → 主 AI 先派两个侦察并行找相关代码
  → 自己写实现
  → 派帮手补测试并运行
  → 派审查看 diff、跑测试
  → 按审查意见再派帮手修一轮
  → 汇报、交付、结束
```

任务页能看到每个子代理的角色、模型、状态和花费；账本按角色分列。

### 11.2 有验收标准的一次性修复

```text
目标：修复登录页在 390px 下的横向滚动，并补一条回归测试
验收命令：pnpm vitest run tests/login.spec.ts
判定：命令 + AI 复核
上限：4 轮 / $0.6 / 1 小时
```

执行者第一次只改样式没补测试 → 命令通过但 AI 判定不通过 → 差距发回 → 补测试 → 通过后结束。

### 11.3 写一弧小说

```text
书库 → 开新书（灵感 + 仙侠 + 每章 2500–3500 字 + 3 卷 × 100 章）
  → 生成设定书，确认
  → 写第一弧（一张工单，N 章）
  → 每章走 contract/draft/review/extract/validate/commit
  → 弧完成，报告回到控制台/飞书
  → 看章节、提修改意见、写下一弧
  → 完成后导出 TXT 或同步番茄
```

## 12. 边界与限制

- **单人系统**：没有多租户、计费和组织隔离；不要把控制台直接暴露到公网。
- **Linux 部署**：真实沙箱依赖 rootless Podman、systemd 和 Pi 镜像；Windows 只适合开发和测试。
- **模型能力**：结果取决于上游模型和提示词；判定模型可能偏严或偏松，目标验收建议保留 AI 复核。
- **小说题材**：目前只支持仙侠和玄幻，其他题材需要扩展 schema 和提示词。
- **番茄**：依赖账号主人提供的 Cookie；站点改版或风控变化可能导致同步失败，控制台会提示。
- **成本**：没有硬性总账户上限，只有单票和每日预算；高價模型（如 Opus）很容易占掉一张票的大部分花费。
